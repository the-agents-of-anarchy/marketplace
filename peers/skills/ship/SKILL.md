---
name: ship
description: >
  Ship an enacted protocol change as the scribe: write it into the peers plugin and the pointer, raise the versions, and announce it to every live peer in one notice.
  "ship the protocol", "bump the protocol version", "write the change into the skills", "announce the new protocol version", an enacted protocol draft to ship, or a `[notice] protocol v<N>` to send.
---

<take-the-terms>
Take `skill`, `hook`, `plugin`, `member`, `protocol`, `card`, `owner`, `bringing a matter to the owner`, `[notice]`, `live`, `peer`, `stewardship`, `scribe`, `pointer`, `change line`, `protocol change`, `draft`, `enacted`, `separating`, and `shipping` as the skill `ontology` defines them; never take them in another sense.
</take-the-terms>

<serve-as-the-scribe>
Treat the stewardship `protocol` as a stewardship like any other; never treat it as an office above the peers.
</serve-as-the-scribe>

<keep-the-text>
Keep the canonical protocol text — the peers plugin's skills, its hook text, and the pointer — as the scribe; never write it without the stewardship `protocol`.

Keep the pointer; never delete it.

Write into the protocol text what the peers consented to; never write a change they did not consent to.
</keep-the-text>

<ship-the-change>
Edit the peers plugin's skills, and the hook text where it changes, to ship an enacted change; never ship from memory of the draft.

Raise the version in the skill `card`'s instruction ``Carry `protocol: <N>` `` to the version you ship; never ship with that instruction behind.

Bump the plugin's version for each shipped change — its last number for a fix, its middle number for a rule or a breaking change while its first number stays 0; never keep a breaking change back for a first-number bump.

Append to the pointer the new version and a dated change line naming any separated project; never let the pointer lag a shipped change.

Send `[notice] protocol v<N>`, carrying the change lines and the path to the change, to every live peer and every member the draft reached, by the skill `tell`; never let the pointer carry a change alone.

Bring the owner a card outside a separated project whose `protocol` stays below the pointer's version; never fix another member's install.
</ship-the-change>
