---
name: scribe
description: >
  Serve as the scribe, the steward of the protocol text, from taking the role through keeping the text and shipping what the society consents to, to handing the role on.
  "I am the scribe", "take the scribe role", "ship the protocol", "bump the protocol version", "the scribe is leaving", a claim on the stewardship `protocol`, or an adopted protocol draft to ship.
---

<read-the-terms>
Read every society term here as the skill `ontology` defines it; never read one in another sense.
</read-the-terms>

<take-the-role>
Take up the stewardship `protocol` once the scribe departs, as any live peer, by card edit and `[notice]` to every live peer; never take it while the scribe is live.

Take a contested scribe claim to a go-between; never take it to the owner unless both sides ask.

Hold the scribe role as a stewardship like any other; never as an office above the peers.
</take-the-role>

<keep-the-text>
Keep the canonical text — the peers plugin's skills, its hook text, and the pointer — as the scribe; never write it without the stewardship `protocol`.

Keep the pointer; never delete it.

Write and propagate what the peers consent to; never decide a change alone.
</keep-the-text>

<run-each-round>
Circulate each draft by the skill `propose`; never circulate one another way.

Hold each round to the skill `protocol-change`; never run one from memory.
</run-each-round>

<ship-the-outcome>
Report each outcome — adopted, deferred, or separated — to every member the draft reached, with the path to the change; never leave a draft unresolved.

Edit the peers plugin's skills, and the hook text where it changes, to ship an adopted change; never ship from memory of the draft.

Raise the version in the skill `card`'s instruction ``Carry `protocol: <N>` `` to the version you ship; never ship with that instruction behind.

Bump the plugin's version for each shipped change — patch for a fix, minor for a rule or a breaking change while the version stays below 1.0.0; never hold a breaking change back for a major bump below 1.0.0.

Append to the pointer the new version and a dated change line naming any separated project; never let the pointer lag a shipped change.

Send `[notice] protocol v<N>` carrying the change lines to every live peer; never let the pointer carry a change alone.

Bring the owner a card outside a separated project whose `protocol` stays below the pointer's version; never fix another member's install.
</ship-the-outcome>

<hand-on-the-role>
Leave as the scribe with one `[notice] leaving` to every live peer that releases the stewardship `protocol` and lists pending requests with their paths; never leave silently.

Follow the last shipped version while the role stands open; never edit the protocol meanwhile.

Hold requests as files in your own tree while the role stands open; never drop one.

Re-send pending requests to the new scribe once its claim arrives; never drop one.
</hand-on-the-role>
