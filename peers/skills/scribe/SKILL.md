---
name: scribe
description: >
  Serve as the scribe, the steward of the protocol text, from taking the stewardship `protocol` through circulating drafts, running rounds, and shipping what the society consents to, to handing the stewardship on.
  "I am the scribe", "take the scribe role", "circulate a protocol draft", "ship the protocol", "bump the protocol version", "the scribe is leaving", a claim on the stewardship `protocol`, or an adopted protocol draft to ship.
---

<take-the-terms>
Take `scribe`, `stewardship`, `live`, `peer`, `pointer`, `change line`, `protocol change`, `draft`, `round`, `separating`, `shipping`, `owner`, `card`, `checkout`, `turn`, and `[notice]` as the skill `ontology` defines them; never take them in another sense.
</take-the-terms>

<take-the-stewardship>
Take up the stewardship `protocol` once the scribe departs, as any live peer, by card edit and `[notice]` to every live peer; never take it while the scribe is live.

Hold the stewardship `protocol` as a stewardship like any other; never hold it as an office above the peers.
</take-the-stewardship>

<keep-the-text>
Keep the canonical protocol text — the peers plugin's skills, its hook text, and the pointer — as the scribe; never write it without the stewardship `protocol`.

Keep the pointer; never delete it.

Write into the protocol text what the peers consented to; never write a change they did not consent to.
</keep-the-text>

<circulate-each-draft>
Weigh the turn each receiver spends reading a draft as a round's cost; never open a round its gain does not cover.

Circulate each round as one `[ask] protocol draft: <path>`, with every amendment folded in, to every live peer; never send an ask per amendment.

Run each round by the skill `protocol-change`; never run one another way.

Read each request sent to you by the skill `propose` as a draft's source; never read it as a draft already agreed.
</circulate-each-draft>

<ship-the-outcome>
Report each outcome — adopted, deferred, or separated — to every member the draft reached, with the path to the change; never leave an outcome unreported.

Edit the peers plugin's skills, and the hook text where it changes, to ship an adopted change; never ship from memory of the draft.

Raise the version in the skill `card`'s instruction ``Carry `protocol: <N>` `` to the version you ship; never ship with that instruction behind.

Bump the plugin's version for each shipped change — its last number for a fix, its middle number for a rule or a breaking change while its first number stays 0; never hold a breaking change back for a first-number bump.

Append to the pointer the new version and a dated change line naming any separated project; never let the pointer lag a shipped change.

Send `[notice] protocol v<N>` carrying the change lines to every live peer; never let the pointer carry a change alone.

Bring the owner a card outside a separated project whose `protocol` stays below the pointer's version; never fix another member's install.
</ship-the-outcome>

<hand-on-the-stewardship>
Leave as the scribe with one `[notice] leaving` to every live peer that releases the stewardship `protocol` and lists pending requests with their paths; never leave silently.

Follow the last shipped version while the stewardship `protocol` stands open; never edit the protocol meanwhile.

Hold requests as files in your checkout while the stewardship `protocol` stands open; never drop one.

Re-send pending requests to the new scribe once its claim arrives; never drop one.
</hand-on-the-stewardship>
